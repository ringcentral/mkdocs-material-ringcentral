# Patterns

Patterns are repeatable solutions to common product problems. Unlike components — which are individual UI elements — patterns describe how multiple components work together to solve a specific interaction challenge.

## When to use patterns vs. components

Use a **component** when you need a single, self-contained UI element (a button, an input field, a card).

Use a **pattern** when you need guidance on composing multiple components to solve a recurring product problem (how to lay out a form, what to show while data loads, how to handle a destructive action).

---

!!! info "Patterns evolve with product feedback"
    Patterns are derived from real product decisions. If you've solved a recurring problem in a way that isn't documented here, reach out to the design systems team to contribute it.
